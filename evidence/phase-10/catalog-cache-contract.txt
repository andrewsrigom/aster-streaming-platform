Workload and covered contract
- Exact bounded Redis read, write-with-expiry, conditional write, delete and
  atomic compare-and-delete operations.
- UTF-8 key limit 256 bytes, value limit 16 KiB and maximum TTL 300 seconds.
- Catalog schema-v1 positive and negative envelopes, exact fence equality,
  deterministic TTL jitter and malformed-value rejection.
- GraphQL entity ordering, duplicates, nulls and public projection remain
  unchanged while the configured cache reader avoids the legacy transaction.
- Finite cache telemetry labels and strict TypeScript, ESLint, Prettier, Knip,
  architecture, security, CI-policy and repository-policy gates.
- A maximum-valid projection larger than 16 KiB bypasses storage, records the
  bypass outcome and does not submit an invalid payload histogram sample.
- Redis decides whether a value exceeds 16 KiB before returning its bytes. Both
  positive and negative corrupt oversized reads retain a malformed outcome
  without an invalid size sample.
- Concurrent mixed batches share each common hot title while newly owned titles
  retain one bounded batch source load.
- Twenty-four concurrent cold absence checks share one in-process owner-fence
  read; two independent readers share one owner-fence read through the negative
  key lease before reusing the short absence marker.
- Coalesced waiter buckets count attached callers behind the owner: a 24-caller
  cold absence burst records one `one`, three `two_to_four` and nineteen
  `five_plus` observations. The two-caller positive path records `one`.
- Fence sharing includes request time and rights-use policy, so calls straddling
  a visibility boundary execute independent owner decisions.
- Redis wrong-type values are classified before size/read operations and enter
  the same exact-key malformed deletion path.
- A bounded control-byte string is accepted as a Redis transport reply, rejected
  by the strict cache-envelope parser and deleted without resetting the shared
  connection or disrupting unrelated keys.
- Negative envelopes include cache time. Missing, future and
  older-than-ten-second values are deleted and rechecked against the owner, so a
  missing or excessive Redis expiry cannot extend public absence.
- Lease acquisition atomically replaces only a wrong-type or non-expiring exact
  key with the caller token and finite TTL; valid finite holders remain
  contended. Monotonic attachment counts are separate from active waiters, so
  mixed-batch cancellation cannot misclassify a later first reattachment.

Interpretation
The local candidate satisfies the written static and focused behavior contract.
Redis is an optional transport behind repository-owned ports; Catalog domain and
application layers do not import a Redis client. The aggregate gate is supporting
candidate evidence, not a release claim.

Initial review
Hosted review comment 3886890023 found that the first implementation submitted
the actual oversized projection as `payloadBytes`, while the telemetry boundary
correctly rejects values above the 16-KiB cache ceiling. The reviewed
implementation omits that non-cacheable size dimension, retains the bypass
counter and adds the valid oversized projection regression. Catalog240/240 and
the repeated73/73 affected gate pass.
