telemetry policy. Both reported bypasses fail their mutation regressions.

Verified composition
- Public SSR/browser Apollo uses HttpLink plus one bounded fetch. There is no
  RetryLink. Streaming replay is blocked; only an explicit UI refresh can issue
  another public request.
- Router has one three-second request deadline, operation-specific subgraph
  timeouts and no retry configuration. The repository source contract now fails
  if a retry block is introduced silently.
- Only the purpose-separated service client owns the selected safe-read retry.
  It uses the shared parent deadline, one jittered delay and at most two total
  attempts. Permanent HTTP, malformed, oversized or invalid owner data gets one
  attempt and fails closed.
- Unsafe progress, profile, publication and deletion mutations gain no hidden
  request retry. Explicit identical-key replay and durable event redelivery are
  separate idempotent operations, not stacked retries of one HTTP request.

Interpretation
One user read produces one Web-to-Router call and one Router-to-subgraph call.
Only the service's fixed safe Catalog read can make a second dependency attempt.
The path therefore remains 1 x 1 x at-most-2, rather than multiplying retries
at each layer.

Limitations
- The check covers the repository's first-party Web, pinned Router configuration
  and two current safe-read owners. It does not claim behavior for an external
  proxy, CDN or future hosted gateway.
- Event-delivery backoff and explicit user retry are intentionally outside this
  synchronous amplification count and remain separately bounded.
