Observed saturation behavior
- Discovery search admits two active calls and one FIFO waiter for at most 100
  ms. The fourth concurrent call returns LIMIT_EXCEEDED without reaching owner
  work. Releasing the first permit admits the waiter; active/waiting return to
  zero. Home rails remain successful while the search lane is full.
- Catalog GraphQL admits eight active requests. The ninth returns bounded HTTP
  503 without entering owner work. Shutdown aborts the eight and later requests
  remain rejected. Its independent process-global rate lane allows 64 calls,
  returns HTTP 429 on overflow and refills at the next measured interval.
- The PostgreSQL adapter configured with one connection reserves the stalled
  acquisition. Caller cancellation returns aborted, but capacity remains
  reserved until the late acquisition is destroyed. A concurrent call returns
  {status: rejected, reason: capacity_exceeded}; reserved slots then return to
  zero. No request enters the vendor waiting queue beyond the configured bound.
- Web server transport admits sixteen active Router sockets. The seventeenth is
  rejected immediately. Cancelling the sixteen releases all capacity and the
  next request succeeds.
- Discovery's Catalog snapshot client admits one live call with no queue;
  Playback's Catalog publication client admits four. Overflow is unavailable,
  cancellation settles every admitted call and later capacity is reusable.
- Media process execution has a finite time/output boundary. A timed-out parent
  and its spawned child are terminated as one owned process group; the test
  observes only a gone or zombie child before deleting its exact temporary file.

Interpretation
Finite application and adapter admission prevents a slow optional search,
database acquisition, owner HTTP dependency, Web socket or media process from
creating an unbounded queue. Explicit overflow and cancellation preserve
independent capacity. Redis remains non-authoritative and PostgreSQL remains the
durable owner.

Limitations
- This is controlled saturation, not a production throughput or SLO result.
- The PostgreSQL scenario stalls the repository adapter's pool acquisition; it
  does not overload a shared real database host.
- Hosted representative load, soak and capacity tuning belong to Phase 14.
