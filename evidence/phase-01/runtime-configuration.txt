---------------------

Configuration-library decision
------------------------------

Selection: exact-pinned zod@4.4.3 as a private implementation detail of @aster/config.

Problem statement:

- Node.js provides process.env and URL parsing but no typed runtime schema, issue aggregation, or static inference.
- Hand-written per-field parsing would duplicate enum, length, pattern, and URL-protocol behavior while creating separate runtime and TypeScript contracts.
- P01-R03 needs one small schema engine; it does not need a .env loader, framework integration, dynamic configuration service, or schema DSL owned by Aster.

Current primary-source review on 2026-08-26:

- The npm registry reported 4.4.3 as the stable version selected by this work item. It was published on 2026-05-04, outside the repository's 24-hour maturity window.
- The package metadata reports MIT, zero runtime dependencies, registry integrity sha512-ytENFjIJFl2UwYglde2jchW2Hwm4GJFLDiSXWdTrJQBIN9Fcyp7n4DhxJEiWNAJMV1/BqWfW/kkg71UDcHJyTQ==, and an npm registry signature.

Acceptance interpretation
-------------------------

- Process start succeeds only after explicit typed validation.
- Missing, empty, malformed, oversized, and unexpected owned variables fail closed.
- ASTER_ENV never defaults to production or any other environment.
- Every accepted variable has an explicit non-secret or secret classification.
- Success diagnostics omit secret values; failure diagnostics use stable repository-owned issues and omit both values and Zod messages.
- Unrelated host environment entries are outside the owned boundary and remain ignored.
- The implementation performs no network operation and creates no partial dependency or application state.

Limitations
-----------

- The timing and RSS observations are one process pair on one WSL2 host with warm filesystem and pnpm stores; they do not predict service throughput, container memory, native Windows, macOS, or other Linux hosts.
- The clean clone reused the user-level Corepack and pnpm content-addressable stores. It proves an empty repository checkout and frozen materialization, not an empty-machine or cold-registry install.
- Environment-variable confidentiality still depends on the host, orchestrator, process inspection policy, crash handling, and future log callers. P01-R03 proves only the repository-owned loader and diagnostic surfaces.
- The current schema belongs to the Phase 01 reference runtime and deliberately requires PostgreSQL and Redis. Future runtime units with different dependencies require their own schema.
- Dynamic secret retrieval, rotation, hosted secret stores, client-bundle analysis, and runtime logging redaction belong to later owning work.
