QUESTION AND SCOPE
------------------

Question: Can a new checkout start a bounded, health-gated PostgreSQL and Redis checkpoint through one Docker Compose command without host Node.js, hosted credentials, exposed dependency ports, product schema, or unrelated local-resource mutation?

Implemented scope:
- exact PostgreSQL and Redis official images;
- internal Compose network;
- one named PostgreSQL volume at the PostgreSQL 18 official parent mount;
- disposable Redis state with bounded memory and allkeys-lfu eviction;
- dependency health checks;
- one-shot SQL and Redis protocol initialization;
- ongoing status health across both dependencies;
- CPU, memory, PID, startup, health, and shutdown bounds;
- dependency-free policy and adverse tests;
- Docker Compose configuration validation;
- path-aware protected CI smoke candidate.

Explicitly absent:
- Node application or service;
- product schema, migration, or data;
- broker, object storage, telemetry, FFmpeg, router, or GraphQL;
- host port or application URL;
- destructive reset command;
- hosted resource or credential.
