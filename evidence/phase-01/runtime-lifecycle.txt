## Question

Can one transport-neutral Node.js coordinator provide stable health state, idempotent ordered shutdown, a single bounded deadline, removable process-signal ownership, structured failure events, and race-safe HTTP force closure without importing Express, Apollo, database, Redis, broker, or telemetry SDK contracts?

## Hypothesis

A small state machine in `@aster/runtime`, combined with narrow process and Node.js HTTP seams, will stop readiness before traffic, allow eligible in-flight work to finish, force a hung connection at the overall deadline, and complete despite hook or logger failure. Real loopback sockets and a real Unix termination signal will validate the boundaries that deterministic unit fixtures cannot prove.

## Node.js compatibility basis

The pinned Node.js HTTP contract documents that `server.close()` stops new connections and closes idle connections while waiting for active connections. It also documents that `server.closeAllConnections()` force closes established HTTP connections and should be invoked after `server.close()` to avoid a race. The Aster HTTP seam preserves that order even if an explicit force arrives before the asynchronous stop hook runs.

The pinned process contract documents that installing `SIGINT` or `SIGTERM` listeners removes Node.js default exit behavior. The Aster binding therefore records conventional exit codes `130` and `143`, performs bounded resource closure, and lets the event loop finish without calling `process.exit()`.

Official references:

- https://nodejs.org/docs/latest-v24.x/api/http.html#serverclosecallback
- https://nodejs.org/docs/latest-v24.x/api/http.html#servercloseallconnections
- https://nodejs.org/docs/latest-v24.x/api/process.html#signal-events
