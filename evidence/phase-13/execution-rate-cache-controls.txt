  account-partitioned Identity admission, Redis degradation and mandatory
  GraphQL no-store policy.
- Operation demand manifest format version 2 classifies every exact current or
  retained operation as public/account/profile, assigns one finite rate class,
  and records deadline, concurrency and no-store. Exact name coverage and
  derived private scope fail composition.
- Router's GraphQL service overwrites admitted responses with
  Cache-Control: no-store. The fixed pre-service oversized-body rejection
  contains no data, explicit freshness or cache validators.
- Identity create/update/delete use profile_mutation (burst 8, refill 2/s);
  selection uses profile_selection (burst 16, refill 4/s). Canonical input,
  authorization and durable receipt lookup run before admission; missing
  receipts proceed to the limiter and repeat authorization before a write.

CORRECTED BEHAVIOR

- Create/update/delete derive admission from the validated durable mutation ID
  plus a canonical request digest. Exact retries share one decision; a changed
  payload remains a different attempt. Selection keeps a fresh identity.
- The shared Redis decision runs before outage-only local admission. A valid
  cross-replica retry is not hidden by one process's exhausted fallback bucket.
- Degraded local admission is bounded by 1,024 account-operation buckets and
  8,192 expiring admission markers, including same-process retry deduplication.
- Router uses the supported Rhai response boundary for no-store on every
  admitted response. The pre-service body-limit rejection is accepted only
  when it is bounded, data-free and advertises neither reusable freshness nor
  validators.
- The real Identity integration records the exact not-ready health/status/code
  fact and separates the rate-exhaustion scenario from later authorization
  assertions. The CI failure diagnostic now includes bounded Router logs.

SECOND CORRECTED BEHAVIOR

- Create/update/delete now validate the canonical request, authorize the current
  session and read the retained PostgreSQL receipt before rate admission.
- An exact retained receipt returns its original result without consulting or
  recreating the 30-second Redis/local marker. Reuse of the same mutation ID
  with a changed payload conflicts before admission.
- Only a missing receipt reaches the account-partitioned limiter. The existing
  mutation path then repeats owner authorization and performs the durable write.
- This preserves the limiter for new work while making the 86,400-second durable
  receipt, rather than a shorter Redis marker, authoritative for replay.

THIRD CORRECTED BEHAVIOR

- Packaged runtime verification derives the exact bounded name/hash union from
  the persisted manifest. It accepts a current-plus-retained overlap, rejects
  more than two hashes for one name and rejects any demand identity mismatch;
  it no longer assumes a fixed operation count.
- The Identity limiter amortizes expired local-marker pruning before capacity
  on both successful Redis and degraded local decisions. A current marker is
  refreshed or preserved at the bound, while expired lifetime traffic cannot
  permanently prevent later retry deduplication.
