IMPLEMENTATION AND BOUNDARIES
The existing public query consumers use errorPolicy all on preload and consumer. Expected failures render sanitized HTML rather than a thrown client-only boundary. Public transport still rejects malformed, oversized, incomplete and partial-error responses; its catch now sanitizes parser errors as well. Failed data is not an empty collection or a missing-title success.
Refresh is an explicit read with a React pending transition. Previously loaded details are labeled potentially stale only during the bounded refresh; a failure hides them. No Redux copy, durable cache, authorization fallback or background polling was added. Native reload links work without JavaScript. Malformed cursor syntax maps to 404; home locale now follows the same explicit input as browse.
Apollo's pinned streaming implementation automatically forwards failed server preloads in the browser. The browser link now requires the current consumer's active explicit-request callback to open HTTP. This transient scheduling guard is not security authorization and carries no identity data. Initial hydration, including failed SSR, opens no browser GraphQL request. The callback is reset after completion and prevents overlapping clicks.
