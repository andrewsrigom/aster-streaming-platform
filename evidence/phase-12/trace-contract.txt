Implemented contract

- `@aster/telemetry` is the only owner of the OpenTelemetry trace SDK and OTLP
  trace exporter. Public packages consume repository-owned observation types.
- Fixed span names are `aster.http.server`, `aster.dependency.operation` and
  `aster.event.produce`; dimensions come only from exported finite sets.
- Inbound W3C `traceparent` is validated. Invalid or zero context is discarded
  and a local root is still created.
- AsyncLocalStorage scopes active context. A synchronous provider gives the
  current trace/span to the existing redacting structured logger.
- Active/retained spans default to 128 and accept only 1–512. Retention drops
  oldest complete spans and reports the finite dropped count.
- PostgreSQL, Redis, broker, object storage, owner HTTP reads and the media
  coordinator use the same dependency observation boundary.
- Identity and Catalog facts may carry one validated producer context;
  Engagement and Discovery execute durable consumer work and logs inside the
  corresponding linked observation.
- The real Catalog operator scopes its durable event transaction inside a
  finite producer span. This records no dependency metric; the relay records a
  broker dependency only when it actually sends to Kafka.
- The one-shot media coordinator configures the same bounded OTLP exporter from
  the reviewed local endpoint in the actual base-plus-media Compose path and
  performs one bounded final flush.
